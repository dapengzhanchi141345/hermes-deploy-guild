# 05 · Hermes 桌面端安装实战（国内镜像 + 远程通道）

> 结论先行：**桌面端必须走官方 `install.ps1` 且显式加 `-IncludeDesktop`**；国内装不上几乎全是「镜像域名解析不了」和「输出被截断看不到真错」。本文是远程实战沉淀。

## 一、pip 版装不了桌面端（先排除）

| 现象 | 原因 |
|:---|:---|
| `hermes desktop` 报 `Desktop GUI source not found at ...\site-packages\apps\desktop` | pip 包**不含** `apps/desktop` 源码 |
| 反复重试都卡 | 方向错了，pip 路线无解 |

**正解**：官方安装器（自带 git 检出 + 桌面端源码）。

## 二、正确命令（关键：`-IncludeDesktop`）

安装器**默认不构建桌面端**，必须显式开关：

```powershell
& ([scriptblock]::Create((irm https://hermes-agent.nousresearch.com/install.ps1))) -IncludeDesktop -NonInteractive
```

- `-IncludeDesktop`：加桌面端构建阶段（**缺了它就只有 CLI**）
- `-NonInteractive`：跳过交互式 setup（别名 `-SkipSetup`，已废弃拼写但仍兼容）
- `-InstallDir <path>`：残留目录冲突时换目录
- `-SkipBrowser` / `-SkipComputerUse`：跳过浏览器内核/computer-use，提速
- `-Manifest`：打印阶段清单 JSON；`-ShowResolvedPaths`：打印解析出的路径

### 常见拦路错误

```
[X] C:\Users\<u>\AppData\Local\hermes\hermes-agent exists and is not a Hermes git checkout,
    run it elsewhere with --InstallDir <path>.
```
→ 之前的 pip/「Install locally」残留目录挡住了。**改名挪开**再重跑：
```powershell
Move-Item "$env:LOCALAPPDATA\hermes\hermes-agent" "$env:LOCALAPPDATA\hermes\hermes-agent.bak_$(Get-Date -f yyyyMMddHHmmss)" -Force
```

## 三、国内镜像：只认「能解析」的域名（核心坑）

**实测 DNS（远程 Windows）**：

| 主机 | 解析 |
|:---|:---|
| `registry.npmjs.org` | ✅ |
| `registry.npmmirror.com` | ✅ |
| **`npmmirror.com`**（裸域名） | ❌ **ENOTFOUND** |
| `github.com` | ✅ |
| **`objects.githubusercontent.com`** | ❌（GitHub 发布资产，Electron 二进制走这里） |
| `mirrors.huaweicloud.com` / `mirrors.cloud.tencent.com` | ✅ |

**正确镜像配置**（一次写 User 级 + 当前会话）：

```powershell
$reg='https://registry.npmmirror.com'
$em ='https://registry.npmmirror.com/-/binary/electron/'
$eb ='https://registry.npmmirror.com/-/binary/electron-builder-binaries/'
$env:npm_config_registry=$reg; $env:ELECTRON_MIRROR=$em; $env:ELECTRON_BUILDER_BINARIES_MIRROR=$eb
[Environment]::SetEnvironmentVariable('NPM_CONFIG_REGISTRY',$reg,'User')
[Environment]::SetEnvironmentVariable('ELECTRON_MIRROR',$em,'User')
[Environment]::SetEnvironmentVariable('ELECTRON_BUILDER_BINARIES_MIRROR',$eb,'User')
npm config set registry $reg
```

> ⚠️ **别用 `https://npmmirror.com/mirrors/electron/`**（裸域名）→ 直接 `getaddrinfo ENOTFOUND npmmirror.com`，把本来能用的 npm 也搞崩。
> ✅ 二进制镜像一律走 `registry.npmmirror.com/-/binary/...`（已验证 HTTP 200）。

**报错对照**：
- `npm error RequestError: getaddrinfo ENOTFOUND npmmirror.com` → 镜像域名解析不了，换 `registry.npmmirror.com`
- `objects.githubusercontent.com` 不通 → Electron/winCodeSign/nsis 下不来 → 必须设 `ELECTRON_*` 镜像

## 四、手动复跑单步（安装器截断输出时）

安装器只打印 Python traceback、隐藏 npm 真错。直接手动跑那一步拿完整输出：

```powershell
$R="$env:LOCALAPPDATA\hermes\hermes-agent"
$N="$env:LOCALAPPDATA\hermes\tools\node-26.7.0-win32-x64\node.EXE"
$env:Path=(Split-Path $N)+';'+$env:Path
& $N "$R\scripts\build\node-deps.mjs" --source $R --reuse --workspace ui-tui --workspace web --workspace apps/desktop
```
成功标志：`added 1315 packages in 54s`。

**抓全量日志**（安装器输出落盘再回传）：
```powershell
& ([scriptblock]::Create((irm https://hermes-agent.nousresearch.com/install.ps1))) -IncludeDesktop -NonInteractive *>&1 | Out-File "$env:TEMP\hins.log" -Encoding UTF8
```

## 五之二、官方桌面端形态对照（别混）

| 形态 | 平台 | 要求 | 说明 |
|:---|:---|:---|:---|
| **源码脚本 + `-IncludeDesktop`** | Win10/11 | PowerShell + 网络 | 本手册主推；产物 `win-unpacked\Hermes.exe` |
| **MSIX / App Installer** | Win11 **22H2+** | 系统版本门槛 | 自包含，首启无需克隆/编译运行时；`.appinstaller` 登记更新源 |
| **`Hermes-Setup.exe`** | Windows | — | 引导安装程序，本质=下载并配置源码 |
| **DMG** | macOS | macOS 版本 + CPU 架构 | 拖进 `Applications`；自动更新走已签名 ZIP；**老机型可能不支持** |
| **`install.sh`** | macOS/Linux/WSL2 | git/curl/tar/shasum | 只确定出 CLI；桌面端另行确认（**待实测**） |

> ⚠️ **反直觉点**：桌面端**不是** CLI 的次生功能，也没有 `hermes desktop` 这条可用路径。
> 想要 GUI，唯一可靠做法就是**一开始（或重跑）官方安装器带 `-IncludeDesktop`**。

## 五之三、更新后配置丢失

Hermes 升级可能改动配置 schema，表现为 provider 消失 / `no API key` 复活：

```powershell
hermes config check      # 体检
hermes config migrate    # 迁移到新 schema
```
迁移完重跑 `hermes model` 确认端点仍在 `config.yaml` 的 `model.base_url`。

## 六、防火墙

`netsh advfirewall set allprofiles state off` **需要管理员**；普通会话里不报错但不生效（`Get-NetFirewallProfile` 仍 `Enabled=True`）。装桌面端其实**不需要关防火墙**——只需镜像域名可达。

## 七、远程注入通道（向日葵逐字符键入不可靠时）

1. **ntfy 中转（首选）**：本机 `curl -X PUT --data-binary @script.ps1 https://ntfy.sh/<topic>` 发布；远程只敲一句短命令拉取执行：
   ```powershell
   iex (irm https://ntfy.sh/<topic>/raw?poll=1)
   ```
   - `/raw` 会把换行折成空格 → **脚本压成单行（`;` 分隔、勿用 `#` 注释）**
   - 回传：远程 `Invoke-RestMethod -Method Put -Body $text -Uri https://ntfy.sh/<topic2>`，本机读 `/json?poll=1`（JSON 保留换行）
   - 主题名每次换新的，避免旧消息叠加
2. **焦点是丢字真凶**：本机其它窗口（如 python 控制台）抢焦点 → 按键只进去一半。对策：
   - 输字前反复 `SetForegroundWindow` 并校验 `GetForegroundWindow()==hwnd`
   - 每 15 字符重新确认焦点
   - **脚本开头 `user32.ShowWindow(user32.GetConsoleWindow(), 0)` 隐藏自身控制台**（否则它盖住截图区域）
3. **截图**：`ImageGrab.grab(bbox=窗口rect)`；向日葵无输入时会冻结旧帧，可轻微移动鼠标触发刷新。
